**症状**：本地 deploy.ps1 确认输入 y 后，服务器端仍显示"跳过发布公告"，且中间卡约 27 秒（等输入）。
**根因**：服务器 `git pull` 到的 `auto-update.sh` 是**旧版（带 `read -p` 交互确认）**，SSH 命令的 stdin 连到本地终端，`read -p` 在等键盘输入；用户按回车（空）→ 判断为跳过。即：**服务器没部署到最新版（`6df1f5b` 已去掉 read -p）**，而非代码逻辑问题。
**修复（commit `9f11c5e`）**：彻底移除任何 `read -p`，`auto-update.sh` 的 `generate_announcement` 改为**双保险**判断——①脚本参数 `--announce`（`main "$@"` 解析传入）②环境变量 `ANNOUNCE_CONFIRM=yes`；任一为真即发布。同时 `deploy.ps1` 的 SSH 命令改为 `${announceEnv}${remote} ${announceFlag}`（`ANNOUNCE_CONFIRM=yes bash auto-update.sh --announce`）。已推送。
**经验**：SSH 远程命令无 TTY，但 stdin 可能继承本地终端，`read` 会等输入造成卡顿。远程脚本**绝不能用 read 交互**，应把交互放本地 PowerShell（Read-Host）再经参数/环境变量传入。

## 公告脚本最终修复：移到 backend/app/scripts 复用实时挂载（commit 6459109）
**症状**：确认逻辑正常后，仍报 `python: can't open file '/app/scripts/generate_update_announcement.py'`。
**根因**：`docker compose restart` 不会加载新挂载（`./backend/scripts:/app/scripts:ro` 需 `up -d` 重建才生效），服务器未重建容器，`/app/scripts` 仍是旧镜像内容。

**核心经验**：容器内要跑的 CLI 脚本若依赖"新增 volumes 挂载"，会受限于 `restart` 不加载新挂载；**应放到已挂载的目录（如 backend/app）下复用实时挂载**，避免强制 `up -d` 重建。
