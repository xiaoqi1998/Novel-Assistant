## 重要架构发现：skill 与短故事向导是两套独立系统
排查代码确认当前应用存在"双轨"架构：
- **Skill 体系**：`backend/app/skills/*/SKILL.md` → `skill_loader.py` 加载 → `skills.py` 的 `POST /api/skills/chat`，以 SKILL.md 全文+references 作为 system_prompt，走通用对话生成。前端入口 `SkillChat.tsx` / `SkillManage.tsx`。`story-short-write` 属于此体系，是"对话式"创作教练。
- **短故事向导体系**：`ShortStoryWizard.tsx` 等 → `short_stories.py` API → `short_story_ai_service.py`，用的是**内置硬编码 Prompt**（SEGMENT_SYSTEM / STAGE1_SETUP_SYSTEM / FULL_STORY_SYSTEM / SCORE_SYSTEM / CHECKLIST_SYSTEM 等），**完全不消费 skill**。
- 因此对 `story-short-write` SKILL.md 的所有增强，只影响"Skill 聊天"入口，**不会**作用到应用主流的"短故事向导/一键成文"流程。

## 已实现：让短故事向导复用 story-short-write 方法论（本次完成）
采用"writing_constraints 精简约束注入"方案，改动最小、不破坏现有 JSON 校验与流式：
1. **SKILL.md 增加 `writing_constraints` 元数据**（YAML frontmatter 块字符串）：一段约 1076 字的精简爆款方法论，覆盖双线叙事+反转等级(S/A/B/C)、爆点设计、情绪收益点、人物四要素、去AI味实时禁忌、标题+黄金前三句异常细节三件套、读者预期管理(每1000字)、结尾传播力。`skill_loader._parse_yaml_frontmatter` 已支持该字段。
2. **`short_story_ai_service.py` 新增**：
   - `get_short_write_skill_constraint()`：从 `skill_loader.get_all_skills_cached()` 加载 story-short-write 的 writing_constraints，带模块级缓存 + 内置默认约束回退（保证可用）。
   - `_skill_constraint_block()`：返回注入用约束块文本。
3. **21 处注入点**：设定阶段（LOGLINE/TWIST/CLUES/CHARACTERS/AUTO_COMPLETE/灵感模板/STAGE1_SETUP×4）、正文阶段（SEGMENT×2/STAGE2_SEGMENT×2）、精修（POLISH×2）、评分（SCORE）、自查（CHECKLIST）、改进（IMPROVE×2）、扩写（FILL_UP），全部 `system_prompt = XXX_SYSTEM + _skill_constraint_block()`。
4. 已验证：YAML 块字符串正确解析；lint 0 错误；`FULL_STORY_SYSTEM`（单次端到端）未使用故未改。
- 后续若改 skill 方法论，只需改 SKILL.md 的 writing_constraints（注意：约束有模块级缓存，改后需重启/热更进程才生效）。
