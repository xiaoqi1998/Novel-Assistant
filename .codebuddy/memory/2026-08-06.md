## 修复快照创建连续失败（2026-08-06 下午）
章节生成时快照多次 `⚠️ 快照创建失败，使用原始内容`，根因是 `snapshot_service.py` 的 `_build_15dim_snapshot` 把 Organization/CharacterRelationship 当 Character 用不存在的属性，逐个修复：
1. `Organization.is_organization` 不存在 → 去掉该过滤（organizations 表记录本身即组织）
2. `Organization.name` 不存在（组织名在关联 Character 上）→ 新增 `org_name_map`（character_id→name 映射），faction_states 用 `org_name_map.get(org.character_id, "未知组织")`
3. `CharacterRelationship.character_a_id/character_b_id` 不存在 → 改用 `character_from_id/character_to_id`
4. `prompt_service.PLOT_ANALYSIS` 模板第2180行 `{ai_score: 0-0.2, ...}` 未转义 → `str.format()` 把说明文字误当占位符报"缺少必需的参数: 'ai_score'"，改为 `{{ai_score: ...}}`
- 部署链路：本地 commit → push origin/main → 服务器 `bash auto-update.sh`（git pull + 构建 + 重启），本次部署后版本 12d7c4a
- 附带修复：`ChapterAnalysis.tsx` 两处 renderItem 未使用 `index` 参数触发 TS6133 构建失败，已删除
- 经验：模板里的 JSON 示例如 `{key: value}` 必须用 `{{key: value}}` 转义，否则 format 报缺参；可用正则 `\{[a-z_]+:\s` 扫描排查

## 修复 Claude 模型 temperature 400（2026-08-06 晚）
`claude-opus-4-8`（经 new-api 网关转发的 OpenAI 兼容端点）报 400：`temperature: This model does not accept a non-default temperature; omit it (the default is 1)`。
- 根因：用户/默认设置 temperature=0.7，OpenAI 客户端 `_build_payload` 无条件发送 temperature，Claude 系列模型只接受默认值 1
- 修复：`backend/app/services/ai_clients/openai_client.py` 的 `_build_payload` 中，模型名以 `claude` 开头时省略 temperature；temperature 为 None 或 ==1.0 时也省略（等价模型默认）
- 经验：Claude 新模型不再支持任意 temperature，只能省略或传 1；经网关转发同样受限
